📐 Flujo GitOps Desacoplado (Modelo SaviaUp)

Los manifiestos y secretos se gestionan en cobroup.enviroments y se transfieren a la VPS en /opt/cobroup/deploys/<env>. Cada push a un microservicio compila en GHCR y aplica sus manifiestos locales ejecutando rollout restart.

Decisión vigente de identidad. La plataforma utiliza exclusivamente access y refresh JWT. BackendAdmin firma con una clave privada asimétrica externa; el backend operativo valida mediante JWKS y nunca recibe la clave privada. Cada ambiente usa material distinto y el arranque debe fallar si faltan clave, kid, issuer o audiences. Los manifiestos actuales deben adecuarse y superar una nueva auditoría antes de desplegarse.
1. cobroup.enviroments

Al hacer push a dev, qa o main, GitHub Actions sustituye los secretos mediante Python y realiza SCP hacia /opt/cobroup/deploys/<env> y /opt/cobroup/deploys/bootstrap.

2. Repositorios de Microservicios

Al hacer push a los microservicios (Backend, BackendAdmin, Frontends), su CI/CD corre pruebas, sube la imagen a GHCR y por SSH ejecuta kubectl apply -f /opt/cobroup/deploys/<env>/<component>/.

3. Clúster K3s y Rollout Progresivo

K3s descarga la nueva imagen desde GHCR mediante ghcr-secret, reinicia los pods gradualmente con zero-downtime y valida la salud mediante probes en /health.

1
Crear Usuario de Despliegue en la VPS (`deployer`)
Obligatorio

Por seguridad y para evitar otorgar privilegios de root a GitHub Actions, creamos un usuario dedicado llamado deployer:

bash (en la VPS como root) 
# 1. Crear el usuario deployer sin contraseña interactiva
sudo adduser --disabled-password --gecos "" deployer

# 2. Agregar al grupo sudo
sudo usermod -aG sudo deployer

# 3. Crear su directorio SSH con permisos restringidos
sudo mkdir -p /home/deployer/.ssh
sudo chmod 700 /home/deployer/.ssh
sudo chown -R deployer:deployer /home/deployer/.ssh
2
Generar Par de Llaves SSH para GitHub Actions
Obligatorio

Genera un par de llaves Ed25519 exclusivo para el pipeline CI/CD en tu máquina local:

bash (en tu máquina local) 
# Generar par de llaves Ed25519 sin passphrase (presiona Enter)
ssh-keygen -t ed25519 -C "github-actions-cobroup" -f ~/.ssh/cobroup_deployer

En la VPS, autoriza la clave pública generada:

bash (en la VPS) 
echo "PEGA_AQUÍ_EL_CONTENIDO_DE_cobroup_deployer.pub" | sudo tee -a /home/deployer/.ssh/authorized_keys
sudo chmod 600 /home/deployer/.ssh/authorized_keys
sudo chown -R deployer:deployer /home/deployer/.ssh
3
Configurar Acceso a `kubectl` para `deployer`
Obligatorio

Copia el kubeconfig de K3s al perfil del usuario deployer:

bash (en la VPS) 
# 1. Crear directorio .kube
sudo mkdir -p /home/deployer/.kube

# 2. Copiar kubeconfig
sudo cp /etc/rancher/k3s/k3s.yaml /home/deployer/.kube/config

# 3. Asignar propiedad a deployer
sudo chown -R deployer:deployer /home/deployer/.kube
sudo chmod 600 /home/deployer/.kube/config

# 4. Probar ejecución
sudo -u deployer kubectl get nodes

6
Crear Secreto de Descarga GHCR (`ghcr-secret`)
Obligatorio

Genera un GitHub Personal Access Token (classic) con permiso read:packages y ejecuta en la VPS:

bash (en la VPS) 
export GH_USER=""
export GH_PAT=""

for NS in cobroup-dev cobroup-qa cobroup-prod; do
  echo "Creando secreto en $NS..."
  kubectl create secret docker-registry ghcr-secret \
    --namespace="$NS" \
    --docker-server=ghcr.io \
    --docker-username="$GH_USER" \
    --docker-password="$GH_PAT" \
    --dry-run=client -o yaml | kubectl apply -f -
done
7
Instalar Cert-Manager y ClusterIssuer Let's Encrypt
Obligatorio
bash (en la VPS) 
# 1. Instalar Cert-Manager v1.16.2
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.16.2/cert-manager.yaml

# 2. Esperar que los pods estén listos
kubectl wait --namespace cert-manager --for=condition=ready pod --all --timeout=120s

# 3. Aplicar ClusterIssuer de Let's Encrypt para Ingress-NGINX
cat << 'EOF' | kubectl apply -f -
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod
spec:
  acme:
    server: https://acme-v02.api.letsencrypt.org/directory
    email: admin@cobroup.com  # <-- REEMPLAZAR POR EMAIL REAL
    privateKeySecretRef:
      name: letsencrypt-prod-account-key
    solvers:
      - http01:
          ingress:
            class: nginx
EOF

Configurar PostgreSQL y Esquemas Desacoplados
Obligatorio
SQL (dentro de psql) 
-- 1. Crear usuarios por ambiente
CREATE USER cobroup_dev_user WITH ENCRYPTED PASSWORD 'Cobroup_Dev_Password_2026!';
CREATE DATABASE cobroup_dev OWNER cobroup_dev_user;

CREATE USER cobroup_qa_user WITH ENCRYPTED PASSWORD 'Cobroup_Qa_Password_2026!';
CREATE DATABASE cobroup_qa OWNER cobroup_qa_user;

CREATE USER cobroup_prod_user WITH ENCRYPTED PASSWORD 'Cobroup_Prod_Password_2026!';
CREATE DATABASE cobroup_prod OWNER cobroup_prod_user;

-- 2. Crear esquemas identity y operations en dev
\c cobroup_dev
CREATE SCHEMA IF NOT EXISTS identity AUTHORIZATION cobroup_dev_user;
CREATE SCHEMA IF NOT EXISTS operations AUTHORIZATION cobroup_dev_user;

-- 3. Crear esquemas en qa
\c cobroup_qa
CREATE SCHEMA IF NOT EXISTS identity AUTHORIZATION cobroup_qa_user;
CREATE SCHEMA IF NOT EXISTS operations AUTHORIZATION cobroup_qa_user;

-- 4. Crear esquemas en prod
\c cobroup_prod
CREATE SCHEMA IF NOT EXISTS identity AUTHORIZATION cobroup_prod_user;
CREATE SCHEMA IF NOT EXISTS operations AUTHORIZATION cobroup_prod_user;

\q
Conectividad de Pods K3s a PostgreSQL:
Asegúrate de que /etc/postgresql/16/main/postgresql.conf contenga listen_addresses = '*' y que en pg_hba.conf exista la línea: host all all 10.42.0.0/16 md5. Reinicia con sudo systemctl restart postgresql.
